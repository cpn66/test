# Предварительные требования к комплексной технической системе «Цифровой полигон»

## Введение

Настоящий документ описывает минимальные и рекомендуемые требования к вычислительной инфраструктуре для развертывания программного комплекса «Цифровой полигон» — системы для работы с документами ГОСТ, включающей компоненты Backend, Frontend, базу данных PostgreSQL, сервис машинного обучения и брокер сообщений RabbitMQ.

**Важно:** Связь с внешней системой МДМ (Master Data Management) для импорта документов ГОСТ осуществляется **исключительно через защищенный VPN-канал** с применением шифрования и аутентификации.

---

## Требования к операционной системе и развертыванию

### Поддерживаемые операционные системы

Система может быть развернута на следующих операционных системах:

**Российские защищённые ОС (рекомендуется для государственных учреждений):**
- **Astra Linux SE** (Special Edition) — с соответствующей лицензией для серверного использования
- **ALT Linux Server** — с соответствующей лицензией для серверного использования

**Открытые ОС:**
- **Debian 11** и выше
- **Ubuntu 20.04 LTS** и выше (при необходимости)

### Варианты развертывания

**Вариант 1: Развертывание через Docker (рекомендуется)**
- Docker Engine 20.10+
- Docker Compose 2.0+
- Все компоненты развертываются в контейнерах
- Требования к хост-ОС: минимальны (ядро Linux 4.8+)
- Поддерживаемые на всех рекомендуемых ОС

**Вариант 2: Развертывание без Docker (native)**
- Требует установки всех компонентов непосредственно в ОС
- Специфичные требования к ПО для каждого компонента
- Более сложная конфигурация и поддержка

## Требования к отдельным компонентам системы

### Для сервера Backend (`192.168.120.220`)

Сервер реализует бизнес-логику, REST API, управление очередями RabbitMQ, хранилище документов и взаимодействие с внешним API МДМ.

**Минимальные требования:**
- **Процессор:** 16 vCPU
- **Память (RAM):** 32 Gb
- **Диск:**
  - 80 Gb SSD для ОС и приложения
  - 200+ Gb для хранилища документов (рекомендуется SSD или быстрый NAS)
- **Локальная сеть:** 1 Гб/с (требуется для RabbitMQ и доступа ML к хранилищу)
- **Сетевая связь:** VPN-туннель к API МДМ (шифрованное соединение)

**Рекомендуемые требования:**
- **Процессор:** 32 vCPU
- **Память (RAM):** 64 Gb
- **Диск:**
  - 160 Gb SSD для ОС и приложения
  - 500+ Gb для хранилища документов

**Операционная система:**
- Astra Linux SE (с лицензией серверного использования)
- ALT Linux Server (с лицензией серверного использования)
- Debian 11+
- Поддержка Docker / Docker Compose

**Программное обеспечение:**
- При развертывании через Docker: Docker Engine, Docker Compose
- При развертывании без Docker:
  - Nginx (веб-сервер и прокси)
  - PHP 8.2 с расширениями (FPM, PostgreSQL, XML, ZIP, AMQP, intl, ctype, iconv, PCRE, session, SimpleXML, Tokenizer)
  - Composer (менеджер зависимостей PHP)
  - RabbitMQ (брокер сообщений)
  - Apache FOP (генерация PDF)
  - JEuclid (обработка математических формул)
  - NFS Server (для общей файловой системы хранилища)

**Открытые порты:**
- 80 (HTTP) — для Backend API
- 443 (HTTPS) — для защищённого Backend API (опционально)
- 5672 (AMQP) — для RabbitMQ (только для локальной сети)
- 15672 (Management) — для администрирования RabbitMQ (только для администраторов)
- 2049 (NFS) — для доступа к хранилищу документов (только для ML на `192.168.120.219`)

**Дополнительные требования:**
- Размер хранилища документов должен рассчитываться на основе объёма ГОСТ-документов и истории обработки (не менее 200 Gb)
- Резервное копирование данных с периодичностью не менее 1 раза в сутки
- Мониторинг свободного место и нагрузки на хранилище

### Для сервера машинного обучения (ML) (`192.168.120.219`)

Сервер выполняет распознавание текста (OCR), анализ содержимого документов и применение моделей машинного обучения.

**Минимальные требования:**
- **Процессор:** 32 vCPU
- **Память (RAM):** 48 Gb
- **GPU (видеокарты):** 1 x NVIDIA GPU с поддержкой CUDA
  - Минимум: NVIDIA V100 или RTX A2000
  - Рекомендуется: NVIDIA A100 (2 шт.) или RTX 6000
  - **Требуется драйвер NVIDIA 470+ и CUDA Toolkit 11.8+**
- **Диск:**
  - 100 Gb SSD для ОС, приложения и виртуального окружения Python
  - Доступ к хранилищу Backend на `192.168.120.220` через NFS
- **Локальная сеть:** 1 Гб/с (требуется для обращения к RabbitMQ и Backend API)
- **Сетевые соединения:** Только исходящие (к RabbitMQ, Backend API и хранилищу). **Входящие порты запрещены**.

**Рекомендуемые требования:**
- **Процессор:** 64 vCPU
- **Память (RAM):** 96 Gb
- **GPU (видеокарты):** 2-4 x NVIDIA A100 или эквивалент
- **Диск:**
  - 200 Gb SSD для ОС и приложения
  - Доступ к большому хранилищу Backend

**Операционная система:**
- Astra Linux SE (с лицензией серверного использования и поддержкой CUDA)
- ALT Linux Server (с лицензией серверного использования и поддержкой CUDA)
- Debian 11+
- Поддержка Docker / Docker Compose

**Программное обеспечение:**
- При развертывании через Docker: Docker Engine, Docker Compose, NVIDIA Docker Runtime
- При развертывании без Docker:
  - Python 3.9+ с pip и venv
  - NVIDIA CUDA Toolkit 11.8+
  - NVIDIA cuDNN 8.6+
  - TensorFlow 2.13+ (для GPU)
  - EasyOCR (оптическое распознавание текста)
  - Tesseract OCR 4.0+
  - Pillow (обработка изображений)
  - Pandas (анализ данных)
  - PyEnchant (проверка орфографии)
  - Pymorphy3 (морфологический анализ русского языка)
  - ONNX Runtime (для выполнения моделей машинного обучения)
  - Pika (взаимодействие с RabbitMQ)
  - Flask / Waitress (локальный API сервис)
  - PM2 (менеджер процессов)
  - NFS Client (для подключения к хранилищу на Backend)

**Открытые порты:**
- **Входящие:** только 22 (SSH для администрирования, со строгими ограничениями по IP)
- **Исходящие:**
  - 80, 443 (HTTP/HTTPS к Backend API на `192.168.120.220`)
  - 5672 (AMQP к RabbitMQ на `192.168.120.220`)
  - 2049 (NFS к хранилищу на `192.168.120.220`)

**Дополнительные требования:**
- **Обязательно:** Изоляция на уровне межсетевого экрана — ML-сервер не должен быть доступен извне
- Мониторинг загрузки GPU и CPU
- Мониторинг температуры GPU
- Наличие системы охлаждения с пропускной способностью не менее 3-5 кВт
- Источник бесперебойного питания (ИБП) рекомендуется

### Для сервера базы данных (СУБД) (`192.168.120.221`)

Сервер хранит данные приложения, документов и результаты обработки.

**Минимальные требования:**
- **Процессор:** 16 vCPU
- **Память (RAM):** 32 Gb
- **Диск:**
  - 100 Gb SSD для ОС и бинарных файлов PostgreSQL
  - 160+ Gb SSD для данных БД

- **Локальная сеть:** 1 Гб/с
- **Интернет:** опционально (только для обновлений)

**Рекомендуемые требования:**
- **Процессор:** 32 vCPU
- **Память (RAM):** 64 Gb
- **Диск:**
  - 160 Gb SSD для ОС и бинарных файлов
  - 240+ Gb SSD для данных БД (рекомендуется NVMe)
  - Отдельный диск для WAL (100+ Gb SSD)
  - Резервный диск для снимков резервных копий

**Операционная система:**
- Astra Linux SE (с лицензией серверного использования)
- ALT Linux Server (с лицензией серверного использования)
- Debian 11+
- Поддержка Docker / Docker Compose

**Программное обеспечение:**
- При развертывании через Docker: Docker Engine, Docker Compose
- При развертывании без Docker:
  - PostgreSQL 15+ (или PostgreSQL Pro 15+ для усиленной безопасности)
  - Инструменты резервного копирования (pg_dump, pgBackRest)
  - Мониторинг (pg_stat_statements, pgAdmin)

**Открытые порты:**
- 5432 (PostgreSQL) — только для Backend на `192.168.120.220`

**Дополнительные требования:**
- Резервное копирование с периодичностью не менее 1 раза в день
- Репликация на резервный сервер (рекомендуется)
- Мониторинг размера БД и скорости роста
- Механизм очистки старых логов (VACUUM)

## Сеевая архитектура и требования

### Сетевые соединения между компонентами системы

```
Пользователи (Internet/LAN)
    ↓ HTTPS (80, 443)
Frontend (192.168.120.222)
    ↓ HTTP (80, 443)
Backend API (192.168.120.220)
    ├─ PostgreSQL (5432) → СУБД (192.168.120.221)
    ├─ RabbitMQ (5672, локально)
    ├─ Хранилище NFS (2049)
    └─ API МДМ (VPN-туннель, шифрованное)

ML (192.168.120.219) — только исходящие
    ├─ Backend API (HTTP, 80/443) ← исходящее
    ├─ RabbitMQ (5672) ← исходящее
    └─ Хранилище (NFS, 2049) ← исходящее
```

### Требования к VPN для МДМ

- **Тип соединения:** Site-to-Site VPN или Client VPN
- **Шифрование:** AES-256 или эквивалент
- **Аутентификация:** Сертификаты X.509 или PSK (Pre-Shared Key) с сильным паролем
- **Пропускная способность:** минимум 10 Мб/с для стабильного импорта документов
- **Надёжность:** гарантированное время восстановления соединения не более 5 минут
- **Мониторинг:** логирование всех попыток подключения и передачи данных

### Требования к межсетевому экрану (Firewall)

**Входящие соединения:**
- 80/443 на Frontend (для пользователей)
- 22 на всех серверах (для администрирования, только с доверенных IP)

**Исходящие соединения:**
- Backend → PostgreSQL (5432)
- Backend → RabbitMQ (локально, внутренний)
- Backend → API МДМ (VPN-туннель)
- ML → Backend API (80/443)
- ML → RabbitMQ (5672)
- ML → Хранилище NFS (2049)
- Все серверы → интернет (для обновлений пакетов)

**Запрещённые соединения:**
- Любые входящие соединения к ML
- Прямые соединения к PostgreSQL извне Backend
- Прямые соединения к RabbitMQ Management (только для администраторов)

## Требования к отказоустойчивости и надёжности

- **Резервное копирование:** ежедневное для PostgreSQL и хранилища документов
- **Репликация БД:** рекомендуется настроить репликацию на резервный сервер
- **ИБП (UPS):** обязателен для Backend, PostgreSQL и ML
- **Мониторинг:** централизованный мониторинг всех компонентов (Prometheus, Grafana, Zabbix)
- **Логирование:** централизованное логирование в SIEM (ELK Stack или аналог)

## Варианты развертывания

### Вариант 1: Виртуальное окружение (рекомендуется)

Все четыре компонента развертываются как виртуальные машины на гипервизоре (KVM, VMware, Hyper-V).

**Преимущества:**
- Простота управления и расширения
- Изоляция компонентов
- Возможность быстрого резервного копирования

**Недостатки:**
- Небольшие накладные расходы на гипервизор
- Требуется опыт администрирования виртуализации

### Вариант 2: Docker Compose (рекомендуется для быстрого развертывания)

Все компоненты развертываются в контейнерах на одной или нескольких физических машинах.

**Преимущества:**
- Быстрое развертывание (часы вместо дней)
- Простая масштабируемость
- Единообразное окружение на разных ОС

**Недостатки:**
- Требует опыта работы с Docker
- Сложнее отладка в случае проблем

### Вариант 3: Гибридное развертывание

Backend, Frontend и PostgreSQL на виртуальных машинах, ML в контейнере Docker на отдельной физической машине с GPU.

**Преимущества:**
- Гибкость в управлении вычислительными ресурсами
- Оптимизация использования GPU

## Безопасность

- Все компоненты должны быть развернуты в защищённой сети (корпоративный LAN)
- Использование HTTPS/TLS для всех внешних соединений (на Frontend и Backend API)
- Регулярное обновление всех пакетов и зависимостей
- Двухфакторная аутентификация (2FA) для доступа администраторов
- Экранирование всех чувствительных данных (пароли, ключи API) в переменных окружения
- Использование VPN для подключения к внешней системе МДМ (обязательно)
- Мониторинг и логирование всех операций импорта документов

---

## Итоговые рекомендации

1. **Используйте Docker для быстрого запуска:** рекомендуется для тестирования и пилотирования
2. **Используйте Debian 11+ или Astra Linux для production:** проверенные стабильность и поддержка
3. **Инвестируйте в GPU для ML:** это критично для производительности OCR и моделей машинного обучения
4. **Настройте VPN для МДМ заранее:** это обязательное условие для импорта документов
5. **Мониторьте нагрузку на все компоненты:** используйте Prometheus, Grafana или Zabbix
6. **Регулярно делайте резервные копии БД:** минимум ежедневно
7. **Изолируйте ML-сервер на уровне firewall:** это критично для безопасности
