## Введение

Настоящий документ является основанием для выполнения работ по развертыванию и настройке программного комплекса «Цифровой полигон» (далее — Система). Система предназначена для работы с документами ГОСТ и включает компоненты Backend, Frontend, базу данных PostgreSQL, брокер сообщений RabbitMQ и сервисы машинного обучения с поддержкой GPU.

Система обеспечивает обработку, хранение и отображение документов ГОСТ, а также импорт документов из системы мастер-данных (МДМ) через защищённый VPN-канал. Компоненты системы могут развертываться как на виртуальных машинах, так и в контейнеризированной среде Docker.

**Важное примечание:** Все соединения с внешней системой МДМ для импорта документов осуществляются **исключительно через защищённый VPN-туннель** с использованием AES-256 шифрования и сертификатной аутентификации.

## 1. Цель изменения

Обеспечить вычислительными и сетевыми ресурсами продуктивный ландшафт программного комплекса «Цифровой полигон» для работы с документами ГОСТ и импорта документов из МДМ через защищённый VPN.

В рамках изменения необходимо:

- развернуть и настроить Backend, включающий Nginx, PHP-FPM, Symfony и RabbitMQ;
- развернуть базу данных PostgreSQL;
- развернуть Frontend на базе Node.js и Nuxt.js;
- развернуть компоненты машинного обучения на отдельном сервере с GPU (NVIDIA A100/V100);
- обеспечить сетевое взаимодействие между компонентами Системы;
- обеспечить доступ ML к API Backend, файловой системе хранения документов и RabbitMQ;
- настроить защищённый VPN-туннель для взаимодействия Backend с API системы МДМ;
- выполнить проверку доступности и работоспособности Системы;
- выполнить тестирование импорта документов через VPN.

**Назначение Системы:** работа с документами ГОСТ, включая загрузку, обработку, хранение, поиск и отображение документов.

**Владелец создаваемых виртуальных машин:** определяется руководителем проекта.

## 4. Архитектурное решение

### 4.1. Общая архитектура

Система построена по распределенной схеме. Компоненты Системы размещаются на отдельных серверах и взаимодействуют по внутренней сети.

**Уровень представления** — Frontend обеспечивает пользовательский доступ к Системе и отображает документы ГОСТ. Frontend размещается на сервере `192.168.120.222`.

**Уровень бизнес-логики** — Backend реализует обработку запросов, бизнес-логику, работу с документами, взаимодействие с PostgreSQL, RabbitMQ и ML, а также импорт документов из МДМ через защищённый VPN-туннель. Backend, Nginx и RabbitMQ размещаются на сервере `192.168.120.220`.

**Уровень данных** — PostgreSQL обеспечивает хранение данных Системы и размещается на сервере `192.168.120.221`.

**Уровень машинного обучения** — ML-компоненты с поддержкой GPU выполняют распознавание, анализ и обработку документов. Сервер ML `192.168.120.219` не имеет открытых сетевых портов для внешних подключений и взаимодействует с остальной Системой только исходящими соединениями к Backend API, RabbitMQ и файловой системе хранения.

### 4.2. Взаимодействие компонентов

1. Пользователь обращается к Frontend по адресу сервера `192.168.120.222`.
2. Frontend направляет запросы к Backend API на сервер `192.168.120.220`.
3. Nginx принимает внешние HTTP/HTTPS-запросы и передает их приложению Backend.
4. Backend обращается к PostgreSQL на сервере `192.168.120.221` для хранения и получения данных.
5. Backend использует RabbitMQ на сервере `192.168.120.220` для асинхронной отправки задач в очередь.
6. **ML-компонент на сервере `192.168.120.219` инициирует подключение к:**
   - **Backend API** (на `192.168.120.220`) для получения заданий на обработку и отправки результатов;
   - **RabbitMQ** (на `192.168.120.220`) для получения задач из очереди и отправки результатов;
   - **Файловой системе хранения** на `192.168.120.220` для чтения исходных документов и записи обработанных результатов.
7. Backend обращается к API МДМ через защищённый VPN-туннель для импорта документов и связанных данных.

### 4.3. Роль ML-сервера в системе

ML-сервер `192.168.120.219` выполняет следующие функции:

- получение задач из очереди RabbitMQ;
- загрузка документов из общей файловой системы;
- распознавание текста и анализ содержимого документов (OCR с использованием GPU, ML-модели);
- обработка и преобразование документов ГОСТ;
- сохранение результатов обработки в файловую систему;
- отправка уведомлений о завершении задач в Backend через API;
- отправка результатов в очередь RabbitMQ для Backend.

**Важно:** ML-сервер не имеет входящих портов, доступных для внешних подключений. Все взаимодействие инициируется ML-компонентом, что повышает безопасность. **GPU (видеокарта NVIDIA A100 или V100) является обязательным компонентом** для эффективной работы ML-моделей и OCR.

### 4.4. Защищённая интеграция с МДМ через VPN

Программный комплекс «Цифровой полигон» имеет возможность импорта документов ГОСТ из МДМ через API. Все соединения с МДМ осуществляются **исключительно через защищённый VPN-туннель**.

**Требования к VPN:**
- **Тип:** Site-to-Site VPN или Client VPN с поддержкой сертификатов X.509
- **Шифрование:** AES-256 или эквивалент
- **Аутентификация:** Сертификаты X.509 или PSK (Pre-Shared Key) с сильным паролем
- **Пропускная способность:** минимум 10 Мб/с для стабильного импорта документов
- **Надёжность:** гарантированное время восстановления соединения не более 5 минут

**Для обеспечения интеграции необходимо:**

- установить и настроить VPN-соединение между Backend `192.168.120.220` и МДМ;
- разрешить сетевой доступ от `192.168.120.220` к API МДМ через VPN-туннель;
- определить адрес, порт и протокол API МДМ;
- настроить параметры подключения в переменных окружения Backend;
- настроить авторизацию в API МДМ в соответствии с требованиями владельца системы;
- обеспечить журналирование всех операций импорта;
- настроить мониторинг состояния VPN-соединения;
- выполнить проверку успешного получения и обработки документов.

Конкретный URL API МДМ, порт, способ авторизации и формат сообщений определяются владельцем МДМ и указываются в эксплуатационной конфигурации Backend.

## 9. Интеграция с системами ИТ

### 9.1. Системы мониторинга и управления

Необходимо обеспечить возможность мониторинга доступности и состояния серверов и сервисов Системы. Рекомендуется контролировать:

- доступность IP-адресов `192.168.120.219`–`192.168.120.222`;
- состояние Nginx, PHP-FPM, RabbitMQ, PostgreSQL, Frontend и ML-приложения;
- доступность и работоспособность API Backend;
- состояние подключения ML к RabbitMQ и Backend API;
- **состояние VPN-соединения Backend к МДМ;**
- **загрузку GPU на ML-сервере и температуру видеокарты;**
- заполнение дискового пространства на всех серверах и в хранилище;
- загрузку CPU и RAM;
- наличие ошибок в журналах;
- успешность операций импорта документов из МДМ через VPN и обработки ML.

### 9.2. Интеграция с системами информационной безопасности

Необходимость интеграции с антивирусом, DLP, SIEM и WAF определяется подразделением информационной безопасности. При наличии корпоративной системы SIEM рекомендуется передавать в нее журналы Nginx, Backend, RabbitMQ, PostgreSQL, Frontend и ML. **Особое внимание должно уделяться логированию всех операций через VPN-туннель к МДМ.**

### 9.3. DNS и NTP

Серверы Системы должны использовать согласованные DNS-серверы и синхронизировать время с корпоративным NTP-сервером. Синхронизация времени необходима для корректного формирования журналов, обработки очередей и расследования инцидентов. **Это критично для синхронизации операций через VPN.**

### 9.7. Влияние на существующую инфраструктуру

Развертывание Системы требует:

- выделения четырех серверов с адресами `192.168.120.219`, `192.168.120.220`, `192.168.120.221` и `192.168.120.222`;
- настройки сетевого взаимодействия между ними;
- регистрации DNS-записей;
- **установки и настройки VPN-туннеля для соединения Backend с API МДМ;**
- предоставления доступа Backend к API МДМ через VPN;
- правильной настройки прав доступа к общей файловой системе;
- **установки GPU (NVIDIA A100 или V100) на ML-сервер;**
- установки NVIDIA CUDA Toolkit и cuDNN на ML-сервер;
- установки и настройки Docker Engine (при развертывании через Docker).

**Критические требования:**
1. ML-сервер должен быть изолирован сетевым экраном таким образом, чтобы не иметь входящих портов, доступных для внешних подключений.

3. GPU должна быть установлена и протестирована перед запуском ML-сервера.

Изменение существующей инфраструктуры ограничивается созданием сетевых правил, DNS-записей, учетных записей, правил мониторинга и настройкой VPN.

- импорта документов из МДМ через VPN;
- получения ML задач из RabbitMQ;
- обработки документов ML-компонентом с использованием GPU;
- сохранения результатов в хранилище;
- корректности работы всех компонентов в целом;
- стабильности VPN-соединения при длительной работе.
