## Введение

Настоящий документ является основанием для выполнения работ по развертыванию и настройке программного комплекса «Цифровой полигон» (далее — Система). Система предназначена для работы с документами ГОСТ и включает компоненты Backend, Frontend, базу данных PostgreSQL, брокер сообщений RabbitMQ и сервисы машинного обучения.

Система обеспечивает обработку, хранение и отображение документов ГОСТ, а также импорт документов из системы мастер-данных (МДМ) через API. В документе определены цель изменения, архитектурное решение, состав программного обеспечения, размещение компонентов, требования к сетевому взаимодействию, доступу и интеграции с внешними системами.

## 1. Цель изменения

Обеспечить вычислительными и сетевыми ресурсами продуктивный ландшафт программного комплекса «Цифровой полигон» для работы с документами ГОСТ и импорта документов из МДМ через API.

В рамках изменения необходимо:

- развернуть и настроить Backend, включающий Nginx, PHP-FPM, Symfony и RabbitMQ;
- развернуть базу данных PostgreSQL;
- развернуть Frontend на базе Node.js и Nuxt.js;
- развернуть компоненты машинного обучения на отдельном сервере;
- обеспечить сетевое взаимодействие между компонентами Системы;
- обеспечить доступ ML к API Backend, файловой системе хранения документов и RabbitMQ;
- обеспечить взаимодействие Backend с API системы МДМ;
- выполнить проверку доступности и работоспособности Системы.

**Назначение Системы:** работа с документами ГОСТ, включая загрузку, обработку, хранение, поиск и отображение документов.

**Владелец создаваемых виртуальных машин:** определяется руководителем проекта.

## 4. Архитектурное решение

### 4.1. Общая архитектура

Система построена по распределенной схеме. Компоненты Системы размещаются на отдельных серверах и взаимодействуют по внутренней сети.

**Уровень представления** — Frontend обеспечивает пользовательский доступ к Системе и отображает документы ГОСТ. Frontend размещается на сервере `192.168.120.222`.

**Уровень бизнес-логики** — Backend реализует обработку запросов, бизнес-логику, работу с документами, взаимодействие с PostgreSQL, RabbitMQ и ML, а также импорт документов из МДМ через API. Backend, Nginx и RabbitMQ размещаются на сервере `192.168.120.220`.

**Уровень данных** — PostgreSQL обеспечивает хранение данных Системы и размещается на сервере `192.168.120.221`.

**Уровень машинного обучения** — ML-компоненты выполняют распознавание, анализ и обработку документов. Сервер ML `192.168.120.219` не имеет открытых сетевых портов для внешних подключений и взаимодействует с остальной Системой только исходящими соединениями к Backend API, RabbitMQ и файловой системе хранения.

### 4.2. Взаимодействие компонентов

1. Пользователь обращается к Frontend по адресу сервера `192.168.120.222`.
2. Frontend направляет запросы к Backend API на сервер `192.168.120.220`.
3. Nginx принимает внешние HTTP/HTTPS-запросы и передает их приложению Backend.
4. Backend обращается к PostgreSQL на сервере `192.168.120.221` для хранения и получения данных.
5. Backend использует RabbitMQ на сервере `192.168.120.220` для асинхронной отправки задач в очередь.
6. **ML-компонент на сервере `192.168.120.219` инициирует подключение к:**
   - **Backend API** (на `192.168.120.220`) для получения заданий на обработку и отправки результатов;
   - **RabbitMQ** (на `192.168.120.220`) для получения задач из очереди и отправки результатов;
   - **Файловой системе хранения** на `192.168.120.220` для чтения исходных документов и записи обработанных результатов.
7. Backend обращается к API МДМ для импорта документов и связанных данных.

### 4.3. Роль ML-сервера в системе

ML-сервер `192.168.120.219` выполняет следующие функции:

- получение задач из очереди RabbitMQ;
- загрузка документов из общей файловой системы;
- распознавание текста и анализ содержимого документов (OCR, ML-модели);
- обработка и преобразование документов ГОСТ;
- сохранение результатов обработки в файловую систему;
- отправка уведомлений о завершении задач в Backend через API;
- отправка результатов в очередь RabbitMQ для Backend.

**Важно:** ML-сервер не имеет входящих портов, доступных для внешних подключений. Все взаимодействие инициируется ML-компонентом, что повышает безопасность.

### 4.4. Интеграция с МДМ

Программный комплекс «Цифровой полигон» имеет возможность импорта документов ГОСТ из МДМ через API. Инициатором взаимодействия является Backend на сервере `192.168.120.220`.

Для обеспечения интеграции необходимо:

- разрешить сетевой доступ от `192.168.120.220` к API МДМ;
- определить адрес, порт и протокол API МДМ;
- настроить параметры подключения в переменных окружения Backend;
- настроить авторизацию в API МДМ в соответствии с требованиями владельца системы;
- обеспечить журналирование операций импорта;
- выполнить проверку успешного получения и обработки документов.

Конкретный URL API МДМ, порт, способ авторизации и формат сообщений определяются владельцем МДМ и указываются в эксплуатационной конфигурации.

### 9.6. Правила доступа в Интернет

Исходящий доступ в Интернет предоставляется только при необходимости:

- обновления пакетов Debian;

- загрузки языковых моделей и компонентов ML;
- обращения Backend к внешнему API МДМ, если API размещен вне корпоративной сети;

Входящие соединения из Интернета к PostgreSQL, RabbitMQ и ML должны быть запрещены. Пользовательский доступ к Frontend ограничивается согласованными сетевыми зонами.
